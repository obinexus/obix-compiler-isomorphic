# obix-compiler-isomorphic

> Previous name: `@obinexusltd/obix-compiler-isomorphic` — OBIX packages are named without an npm scope since decision D-102 (2026-09-29); the package, its version and its exports are unchanged.

Server-side rendering for OBIX. The same component definition you mount in the browser renders
here to an HTML string, with no DOM anywhere in the path.

```ts
import { renderToString } from 'obix-compiler-isomorphic';

const html = renderToString(Counter);           // initial state
const later = renderToString(Counter, { count: 5 });
```

```text
state -> render -> fudguard -> HTML string
```

- Uses the same deterministic renderer and the same accessibility enforcement as the browser
  runtime, so server and client produce the same initial markup for the same state.
- Throws `FudViolationError` if the output breaks an accessibility policy.
- Importing this package and calling `renderToString` never touches `window`, `document`,
  `HTMLElement`, `customElements`, `MutationObserver` or `matchMedia`. The package is compiled
  without the DOM lib, and its tests scan the built output for those globals.

## Environment detection

```ts
import { isBrowser } from 'obix-compiler-isomorphic';
```

`isBrowser()` is a `typeof` probe for use at adapter boundaries (choosing a server or client entry
point). Do not call it inside a component's `render`.

## Hydration handoff

Kept out of the server entry point, in its own subpath:

```ts
import { hydrate } from 'obix-compiler-isomorphic/hydrate';
import { mount } from 'obix-compiler-reactive';

const { matches } = hydrate(Counter, document.getElementById('app')!);
mount(Counter, '#app'); // the browser runtime takes over
```

`hydrate` only checks that the server markup equals the component's initial render (a textual,
whitespace-normalised comparison). It never mounts anything and never imports the browser runtime.

## Scope

Owns server rendering. It depends only on `obix-compiler-fudguard`; it must not import
the reactive DOM runtime.
